# Руководство пользователя PrivacyGuard 3.1

## Первый вход и документы
1. Открой приложение по HTTPS или `http://localhost`.
2. Войди через Email/Password или Google.
3. Прочитай пользовательское соглашение, политику конфиденциальности и правила допустимого использования. Каждый документ открывается на отдельной вкладке.
4. Установи три отдельные галочки. Они не выбраны заранее.
5. Нажми «Подтвердить и продолжить». Приложение запишет версии документов и серверную дату в Firestore по пути `users/{uid}/legalAcceptances/{versionId}`.
6. Если Firestore Rules ещё не обновлены, появится `PG-FS-403`. Администратор проекта должен опубликовать `firestore.rules`.
7. В любое время открой раздел «Документы и соглашения», чтобы перечитать условия и проверить версию принятия.

## Рабочие пространства
- «Мои проекты»: группируй активы и заметки по рабочим пространствам.
- «Мои активы»: добавляй только собственные домены/IP или ресурсы с разрешением.
- «Мониторинг»: вручную запускай повторную проверку и сравнивай снимки.
- «Центр отчётов»: создавай отчёт, скачивай JSON/CSV или используй печать → «Сохранить как PDF».
- «Уведомления»: просматривай события и помечай их прочитанными.
- «Избранное»: закрепляй часто используемые разделы.
- `Ctrl+K` / `Cmd+K`: открой глобальный поиск.

## Security Lab
- **DNS Explorer** — получает публичные DNS A/AAAA/MX/TXT/NS/CAA/SOA/DS/DNSKEY-записи через Google Public DNS over HTTPS.
- **Password Exposure Check** — локально считает SHA-1, отправляет только первые 5 символов хеша в Have I Been Pwned, затем сравнивает суффиксы в браузере. Пароль не сохраняется в Firestore и очищается из поля.
- **NVD / CVE Quick Search** — ищет CVE по ключевому слову в NIST NVD API 2.0. Публичный лимит без ключа — до 5 запросов за скользящие 30 секунд; в интерфейсе действует локальное ограничение. При HTTP 429 дождись окна сброса лимита.

## Новости и источники
В разделе «Справка и источники» собраны официальные первоисточники: CISA Alerts/KEV, NIST NVD и NVD News, ENISA, EDPB, OWASP, MDN, Firebase и Have I Been Pwned. Нажатие открывает сайт издателя. Приложение не придумывает заголовки и не выдаёт статический список ссылок за свежую новостную ленту. Проверь дату публикации и первоисточник.

## Offline Lab
Если соединение пропало, Service Worker показывает отдельную страницу `offline.html`. На ней доступны полностью локальные инструменты:
- JSON Formatter и Minifier;
- Base64 Encoder / Decoder (UTF-8);
- SHA-256 через Web Crypto;
- генератор случайных паролей;
- UUID v4;
- Unix Timestamp Converter;
- диагностика сети, Service Worker и localStorage;
- справочник кодов ошибок.

Эти функции выполняются в текущем браузере и не передают содержимое на сервер. Offline Lab не синхронизирует данные с Firebase. Внешние API, вход, новости и облачные изменения требуют подключения.

## Безопасность кэша
Постоянный кэш Firestore по умолчанию выключен. Включай его только на своём доверенном устройстве через чекбокс «Это моё личное устройство». Firebase web persistence может сохранять локальные данные и после выхода из аккаунта; не включай его на публичных/общих устройствах. Изменение применяется после полного перезапуска. Обычный Service Worker кэширует только оболочку и локальные файлы, а не приватные API-ответы.

Кнопка «Запросить защиту локального хранилища» пытается вызвать `navigator.storage.persist()`. Браузер может отказать, а это действие не является резервным копированием.

## Диагностика
- `PG-NET-001` — соединение отсутствует или запрос не выполнен.
- `PG-FS-403` — Firestore запретил действие; проверь Firebase UID и Rules.
- `PG-AUTH-401` — требуется вход или повторная аутентификация.
- `PG-SRC-408` — источник не ответил вовремя.
- `PG-404` — страница или ресурс не найден.
- `PG-APP-500` — внутренняя ошибка приложения.

`404.html` является пользовательской страницей Not Found на Firebase Hosting. Статусы 403 и 500 определяются сервером/хостингом; файлы `403.html` и `500.html` — дизайн-шаблоны, а не способ принудительно назначить HTTP status.
